# 쏘플 공간관리 시스템

직영점의 청소 · 시설 · 홍보채널 · 매출/손익을 한 화면에서 관리하는 웹 시스템입니다.
예약 현황을 넣어두면 밤타임(19:00~익일 10:00)과 낮타임(12:00~17:00) 사이의 청소 일정이
자동으로 만들어지고, 근무자 배정 → 체크리스트 수행 → 총괄관리자 확인·피드백까지
한 흐름으로 이어집니다.

터미널이나 별도 프로그램 설치 없이, **브라우저만으로** 배포부터 운영까지 가능합니다.

---

## 폴더 구성

```
index.html                  ← 화면 전체 (이 파일 하나가 앱입니다)
functions/api/[[route]].js  ← 서버 API (Cloudflare가 자동으로 실행)
schema.sql                  ← 데이터베이스 초기화 스크립트 (D1 콘솔에서 1회 실행)
README.md                   ← 이 안내서
```

세 파일의 위치와 이름을 바꾸지 않고 그대로 올리면 됩니다.

---

## 1단계. GitHub에 올리기 (약 3분)

1. github.com 로그인 → 우측 상단 **+** → **New repository**
2. 이름은 자유롭게 (예: `ssople-spms`), **Private** 선택 → **Create repository**
3. 만들어진 저장소 화면에서 **uploading an existing file** 링크 클릭
4. 압축을 푼 폴더의 **내용물 전체**(index.html, functions 폴더, schema.sql, README.md)를
   창으로 끌어다 놓기 → 아래 **Commit changes**

> 폴더째 끌어넣으면 `functions/api/[[route]].js` 경로가 그대로 유지됩니다.
> 혹시 파일만 낱개로 올렸다면, functions 폴더 구조가 살아 있는지 한 번 확인해 주세요.

---

## 2단계. Cloudflare Pages에 연결하기 (약 3분)

1. dash.cloudflare.com 로그인 → 왼쪽 **Workers & Pages** → **Create** → **Pages** 탭
2. **Connect to Git** → 방금 만든 저장소 선택
3. 빌드 설정은 전부 기본값 그대로 둡니다.
   - Framework preset: **None**
   - Build command: (비워두기)
   - Build output directory: `/`
4. **Save and Deploy**

1~2분 뒤 `https://프로젝트명.pages.dev` 주소가 생기고, 접속하면 바로 화면이 뜹니다.
이 상태는 아직 **데모 모드**입니다(아래 설명 참고). 팀이 함께 쓰려면 3단계로 데이터
저장소를 연결해 주세요.

---

## 3단계. 데이터베이스(D1) 만들기 — 실사용 전환 (약 4분)

여기가 유일하게 "설정"다운 작업인데, 전부 클릭과 붙여넣기입니다.

1. Cloudflare 왼쪽 메뉴 **Storage & Databases** → **D1 SQL Database** → **Create**
2. 이름: `ssople-ops` → **Create**
   > 기존에 쓰고 계신 `ssople-host` 데이터베이스와는 **완전히 별개**입니다.
   > 그쪽은 건드리지 않습니다.
3. 만들어진 `ssople-ops` 클릭 → **Console** 탭
4. 압축 파일 안의 **schema.sql**을 메모장으로 열어 내용 **전체 복사** → 콘솔에 붙여넣기
   → **Execute** → 초록색 성공 표시 확인
   > 여러 번 실행해도 안전하게 만들어 두었습니다.

### 사이트와 연결하기

5. 다시 **Workers & Pages** → 2단계에서 만든 프로젝트 → **Settings**
6. **Bindings** 항목에서 **Add** → **D1 database**
   - Variable name: `DB`  ← 대문자 두 글자, 정확히 이대로
   - D1 database: `ssople-ops`
   → **Save**
7. 프로젝트의 **Deployments** 탭 → 최근 배포 오른쪽 **⋯** → **Retry deployment**
   (연결 설정은 새 배포부터 적용되기 때문입니다)

새로 배포가 끝난 뒤 사이트를 새로고침하면 **"처음 설정"** 화면이 나옵니다.
혹시 "데이터베이스 준비 필요"라는 화면이 보이면 4번(schema.sql 실행)을 건너뛴
경우이니, 실행 후 화면의 버튼으로 다시 확인하면 됩니다.

---

## 4단계. 처음 설정과 계정 발급

1. 사이트에서 이름 · 아이디 · 비밀번호를 넣어 **대표 계정**을 만듭니다.
   5개 직영점, 공통 체크리스트 20항목, 지점별 홍보채널 11종은 자동으로 준비됩니다.
2. **설정 → 계정 관리**에서 팀원 계정을 만들어 아이디/비밀번호를 전달합니다.

| 역할 | 볼 수 있는 것 | 할 수 있는 것 |
|---|---|---|
| 대표 | 전체 | 전체 + 계정 발급 |
| 총괄관리자 | 전체 | 청소 확인·피드백, 예약·비용·설정 관리 |
| 청소근무자 | 담당 지점의 청소 일정만 (고객 이름·연락처·금액은 안 보임) | 체크리스트 수행 · 완료 제출 · 시설 이슈 신고 |
| 시설관리자 | 시설 이슈, 담당 지점 청소 현황 | 이슈 확인·진행·완료 처리 |

계정마다 **담당 지점**을 지정해 두면 그 지점 일정만 보입니다.
비밀번호를 잊으면 대표가 계정 관리에서 새 비밀번호로 재설정해 주면 됩니다.

---

## 매달 하는 일 (10초 루틴)

**예약 올리기** — 청소관리 → 예약 등록 탭, 또는 KPI·손익 → 예약 업로드 탭에
`쏘플파티룸_직영점_9월_예약매출현황.xlsx` 같은 월 파일을 끌어다 놓고 **교체**를 누르면
끝입니다. 해당 월의 기존 엑셀 데이터를 지우고 새로 넣기 때문에, 파일을 다시 받을
때마다 같은 방식으로 올리면 항상 최신 상태가 됩니다. 지점명이 조금 달라도
설정의 별칭으로 알아서 매칭되고, 매칭이 안 된 지점은 업로드 화면에서 직접
골라줄 수 있습니다.

**비용 넣기** — KPI·손익 → 비용 입력 탭에서 지점별 임대료 · 관리비 · 물품비 ·
통신비 · 기타와 수수료율(%)을 넣고 저장하면 지점별 영업이익과 이익률이
바로 계산됩니다. "전월 비용 불러오기"로 지난달 값을 복사해 숫자만 고치면 빠릅니다.

수기 예약이나 취소 반영은 예약 등록 탭에서 날짜 칸을 눌러 바로 처리할 수 있습니다.

## 데모 모드란?

서버(D1)가 연결되지 않은 상태에서는 자동으로 **데모 모드**로 열립니다.
모든 기능이 똑같이 동작하지만, 데이터가 **그 브라우저에만** 저장됩니다.
혼자 미리 둘러보거나 팀 교육용으로 쓰기에 좋고, 설정 → 데이터·연결에서
백업(JSON) 내려받기와 초기화가 가능합니다. 실사용 데이터는 3단계 연결 후
새로 입력하는 것을 권합니다.

## 자주 묻는 것

**화면을 수정한 새 index.html을 받았어요.**
GitHub 저장소에서 index.html을 열고 휴지통 아이콘 대신 새 파일을 같은 이름으로
다시 업로드(덮어쓰기) → Commit 하면 1~2분 내 자동 반영됩니다.

**pages.dev 말고 우리 주소를 쓰고 싶어요.**
Pages 프로젝트 → **Custom domains**에서 보유 도메인을 연결하면 됩니다.

**데이터가 안 보이거나 로그인 화면이 반복돼요.**
Settings → Bindings의 변수 이름이 `DB`인지, schema.sql을 실행했는지,
그 뒤 **Retry deployment**를 했는지 순서대로 확인해 주세요.

**host.jssystems.kr에서 자동으로 가져올 수는 없나요?**
현재는 월 엑셀 업로드 방식이 기본입니다. 자동 수집으로 넓히는 방법은
전달드린 안내를 참고해 주세요. 시스템 쪽은 예약 데이터가 어떤 경로로 들어와도
받도록 만들어져 있어서, 나중에 자동화를 붙여도 구조 변경이 없습니다.
