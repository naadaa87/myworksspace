# 쏘플 공간관리 시스템 v2 (1단계)

직영 파티룸의 **예약 → 청소 배정 → 현장 체크리스트 → 확인 → 손익**을 한 화면에서 관리하는 웹 시스템입니다.
서버 비용 0원(Cloudflare 무료 플랜), 설치와 운영 모두 **브라우저만으로** 가능합니다.

이번 v2(1단계)에서 추가된 것
- **주간 운영 보드** — 요일별로 예약·청소·담당을 한눈에, 인쇄·PDF·이미지(단톡 공유용) 내보내기
- **일괄 배정** — "이 날 신촌 권역은 ○○" 한 번이면 그날 해당 청소 전체에 자동 적용
- **지점 운영 프로필** — 지점마다 운영시간·표준 소요·버퍼·중간마감·특이규칙·기본 담당을 따로 설정
- **긴급 · 마감 · 확인 후 진행 표시** — 가용 시간이 짧으면 "긴급 · 가능 2시간 · 현장 대기", 다음 입실이 먼 날이면 "~10/8 13:30까지 완료", 확인이 필요한 예약은 보류 배너
- **일일 브리핑** — 필수 확인사항을 올리면 근무자 홈 상단에 뜨고, "확인했습니다" 읽음 명단이 남음
- **호스트 예약 자동 동기화** — host.jssystems.kr 예약이 자동으로 들어옴 (아이디·비밀번호 불필요, 아래 설명)
- **인건비 자동 집계** — 확인완료된 청소 건수 × 계정별 건당 단가(기본 15,000원)를 손익에 자동 반영

## 1. 폴더 구성

| 파일 | 역할 |
|---|---|
| `index.html` | 화면 전체 (PC·모바일 겸용) |
| `functions/api/[[route]].js` | 서버 API (Cloudflare Pages Functions) |
| `schema.sql` | **처음 설치용** DB 초기화 (v2 테이블 포함) |
| `upgrade_v2.sql` | **기존 v1 사용자용** 업그레이드 (새 테이블만 추가, 기존 데이터 무손실) |
| `test/api.test.mjs` | 서버 자동 테스트 121건 (참고용, 배포에 불필요) |

> 파일을 열어 보기만 해도 데모 모드로 바로 체험할 수 있습니다. `index.html`을 더블클릭 → "데모로 둘러보기".

## 2. 기존에 v1을 쓰고 있다면 — 업그레이드 3단계 (약 5분)

**① 파일 2개 교체**
GitHub 저장소에서 `index.html`과 `functions/api/[[route]].js`를 각각 열어 ✏️(Edit) → 새 파일 내용으로 전체 교체 → Commit.
(Cloudflare Pages가 자동으로 재배포합니다)

**② 새 테이블 추가 — upgrade_v2.sql 1회 실행**
Cloudflare 대시보드 → Storage & Databases → **D1** → `ssople-ops` → **Console** 탭
→ `upgrade_v2.sql` 내용 전체를 붙여넣고 Execute.
기존 테이블·데이터는 건드리지 않으며, 여러 번 실행해도 안전합니다.
(실행 전까지는 화면 상단에 "업그레이드 SQL 필요" 배지가 뜨고, 기존 기능은 그대로 동작합니다)

**③ 호스트 예약 동기화 연결 — HOSTDB 바인딩**
Cloudflare Pages → 프로젝트 → Settings → **Bindings** → Add → **D1 database**
- Variable name: `HOSTDB`
- D1 database: `ssople-host` (호스트 페이지가 쓰는 기존 DB)
저장 후 Deployments → 최신 배포 → **Retry deployment** → 사이트 새로고침.

끝입니다. 설정 → 데이터·연결에서 **[지금 동기화]**를 눌러 첫 동기화를 확인하세요.

---

## 3. 처음 설치한다면 (신규 · 약 20분, 브라우저만 필요)

1. **GitHub 저장소 만들기** — github.com 가입 → New repository(비공개 가능) → 이 폴더의 파일을 그대로 업로드
2. **Cloudflare Pages 배포** — dash.cloudflare.com → Workers & Pages → Create → Pages → Connect to Git → 방금 저장소 선택 → 빌드 설정은 모두 비워 두고 Deploy
3. **D1 데이터베이스 생성** — Storage & Databases → D1 → Create → 이름 `ssople-ops`
4. **스키마 실행** — 만든 DB의 Console 탭에 `schema.sql` 내용 전체 붙여넣고 Execute (v2 테이블까지 한 번에 생성)
5. **바인딩 연결** — Pages 프로젝트 → Settings → Bindings → D1 database 추가
   - `DB` = `ssople-ops` (운영 DB)
   - `HOSTDB` = `ssople-host` (호스트 예약 읽기 전용 — 2번 항목 ③과 동일)
6. Deployments → Retry deployment → 사이트 접속 → "처음 설정"에서 대표 계정 생성

## 4. 호스트 예약 자동 동기화 — 어떻게 안전한가

- 호스트 페이지(host.jssystems.kr)와 이 시스템이 **같은 Cloudflare 계정** 안에 있기 때문에, 호스트의 예약 DB(`ssople-host`)를 **계정 내부 바인딩**으로 직접 읽습니다.
- 그래서 **아이디·비밀번호를 어디에도 입력하거나 저장하지 않습니다.** 외부 로그인 자동화(크롤링)보다 빠르고, 유출 걱정이 없습니다.
- 이 연결은 **읽기에만** 사용합니다. 호스트 DB에는 어떤 수정·쓰기도 하지 않아 기존 서비스에 영향이 없습니다.
- 동작 방식
  - 관리자가 접속할 때 마지막 동기화가 12시간을 넘었으면 자동으로 1회 실행 + 설정·예약 화면의 **[지금 동기화]** 버튼으로 수동 실행
  - 오늘 기준 **35일 전 ~ 90일 후** 예약을 맞추고, 호스트에서 취소·삭제된 예약은 여기서도 사라집니다
  - 호스트에서 넘어온 예약은 달력에 **빨간색**으로 표시되고 매출·손익에 그대로 집계됩니다
  - 지점 이름이 달라 연결하지 못한 예약은 "미매칭 지점"으로 알려 줍니다 → 설정 → 직영 지점에서 해당 지점의 **지점 코드(S코드)** 또는 별칭에 그 이름을 넣으면 다음부터 자동 연결
- 예약·매출 **엑셀 업로드 기능도 그대로** 남아 있어, 동기화 전 과거 자료 정리나 백업 용도로 쓸 수 있습니다.

## 5. 새 기능 사용법 요약

**주간 운영 보드** (대표·관리자)
좌측 메뉴 🗓️ 주간 보드. 요일마다 청소 건수·동시 진행 지점 수(기준 이상이면 "인력 확인 필요")·미배정·긴급 건수가 보입니다.
"일괄 배정" 칩에서 권역(권역이 없으면 지점) 단위로 담당을 걸면 그날 해당 청소 전체에 적용되고, 개별 카드에서 지정한 담당이 있으면 그쪽이 우선합니다.
상단 **[🖨 인쇄·PDF]**(인쇄창에서 "PDF로 저장" 선택), **[🖼 이미지 저장]**(단톡 공유용 PNG) 버튼으로 내보냅니다.

**지점 운영 프로필** — 설정 → 직영 지점 → 수정.
권역, 지점 코드(S코드), 기본 담당, 표준 소요(분), 입실 전 버퍼(분), 중간 정리 마감, 운영시간(비우면 전역값), 특이규칙을 지점별로 둘 수 있습니다. 특이규칙은 그 지점 청소 체크리스트 상단에 📌로 그대로 표시됩니다.

**긴급 · 마감 · 확인 후 진행**
- 가용 시간이 표준 소요보다 짧으면 → `긴급 · 가능 ○시간 · 현장 대기` (기준은 설정 → 운영시간·규칙 또는 지점별)
- 다음 입실이 다른 날이면 → `~10/8 13:30까지 완료` 마감 표시
- 예약 등록 달력에서 빨간 칸(엑셀·동기화분)을 누르면 **확인 필요 표시**를 걸 수 있고, 해당 청소에는 "관리자 확인 전 시작 금지" 배너가 뜹니다 (근무자에게 메모 내용·개인정보는 보이지 않음)

**일일 브리핑** — 주간 보드 각 날짜 하단 "📢 필수 확인사항 ＋추가".
근무자 홈 상단에 표시되고 [확인했습니다]를 누르면 읽음 명단(누가 언제)이 보드에 남습니다.

**인건비 자동 집계** — 매출·손익 → 지점별 손익에 **인건비(자동)** 열.
그 달 `확인완료`·`제출완료` 청소 건수 × 담당 계정의 건당 단가. 단가는 설정 → 계정 관리에서 계정별로 수정(기본 15,000원, 대표만 변경 가능).

## 6. 계정 권한 (v1과 동일 + 추가)

| 역할 | 할 수 있는 것 |
|---|---|
| 대표 | 전부 + 계정·단가 관리 |
| 관리자 | 보드·배정·브리핑·동기화·검수·손익·설정 |
| 청소근무자 | 내 청소·체크리스트·브리핑 확인·시설 신고 — 예약자 이름·연락처·금액은 안 보임 |
| 시설담당 | 시설 신고 처리 |

## 7. 자주 묻는 문제

- **상단에 "업그레이드 SQL 필요"가 떠요** → 2번 항목 ②의 `upgrade_v2.sql`을 아직 실행하지 않은 상태입니다. 실행하면 사라집니다.
- **[지금 동기화]에서 "HOSTDB가 연결되지 않았습니다"** → 2번 항목 ③의 바인딩 + Retry deployment를 진행해 주세요.
- **동기화 후 "미매칭 지점"이 떠요** → 설정 → 직영 지점에서 그 지점의 지점 코드(S코드)나 별칭에 안내된 이름을 그대로 넣고 다시 동기화.
- **이미지 저장이 안 돼요** → 사내망 등에서 외부 스크립트가 막힌 경우입니다. [🖨 인쇄·PDF]로 저장해 주세요.
